## Use

Create a script with + or the create tile. Edit its title and type or paste text. Library → Import Text opens the native Files picker for UTF-8 plain text, up to 1,048,576 bytes. Invalid or oversized imports fail without truncating text. Search matches titles and text. A script's context menu provides duplication and recoverable deletion; Library → Recently Deleted restores it.

Read & Record opens the P3 reader studio paused at its saved position. Font, pace, alignment, dark/light prompt appearance, opacity, reading band, panel position and height persist. The explicit handles move and resize the prompt; controls sit below it in portrait and beside it in landscape. Manual text scrolling pauses playback. Changing font, alignment or viewport preserves the reading anchor, and Restart returns to the beginning without discarding a take. Checkpoints save at most every ten seconds and flush on pause/exit/backgrounding.

P3D makes the long-script reader use contiguous TextKit layout, one accessible text value and explicit viewport width before restoring a position. This fixes native accessibility stalls, near-end font jumps and a playing-only landscape-to-portrait jump. The existing 500 ms display-gap guard pauses text safely and requires deliberate resume; camera capture continues independently. Camera cleanup also respects the current original-playback audio lease, including delayed setup and dismissal.

Camera mode retains the P1 service with P3B operation identities and recovery. A take freezes its camera, orientation and script snapshot; text starts on the actual recording-start callback. Countdown can be cancelled, and leaving during capture waits for finalization. Current microphone/camera information appears below the controls. Preflight requires about 2 GB based on the measured ten-minute original plus margin and finalization reserve. Capture monitors headroom and stops on relevant interruptions; reentry is deliberate. Playable interrupted files are preserved with a warning, and failed journal publication remains recoverable.

Videos groups original takes by their retained script identity, including older P1 recordings under Other recordings. Search finds retained script titles; aspect-fitted thumbnails, duration/storage and recovery states help identify a take. Open a ready row for native original playback. Context-menu/swipe deletion requires confirmation and leaves the script intact. Missing files offer Remove Details; incomplete files remain preserved and unavailable for playback. Launch/refresh reconcile the journal and originals, including interrupted deletions. Thumbnail cache data can regenerate without rewriting originals. Broader physical acceptance remains a P3 follow-up. The completed short and sustained iPhone 17 Pro tests pass at their documented scope; remaining rear landscape, framing/sync, calls/routes/lock and critical-health checks stay deferred.

Videos → a playable take → Edit Video opens the P4A editor. Drag the timeline handles or use the Start/End frame buttons, scrub within the selection, and play it to check the cut. Playback stops at the selected end and returns to the beginning. Done saves the edit recipe; Cancel discards the draft; Reset restores the full original interval/crop in the draft. Reopen or relaunch to continue saved edits. The original remains unchanged and is still available in the recording view. Crop opens the P4B framing screen: choose Original, 9:16, 16:9, 1:1, 4:5 or Custom. New ratios start centered; drag the grid or use position sliders to move them. Custom adds four corner handles and width/height sliders. Dimensions show the effective even-pixel output without upscaling. Crop Cancel discards only the crop task; crop Done applies it to the editor draft. Editor Done saves trim, framing and selected mode together; editor Cancel discards the entire draft.

P4C adds Export MP4 (Save Edit & Export MP4 when a draft changed). Export explicitly saves the edit, freezes that revision, and creates one H.264/AAC SDR MP4 at the effective crop size. Keep the app open while progress advances. Cancel waits for the encoder to stop and removes its partial work; Retry starts from the frozen saved edit. Backgrounding or termination leaves an interrupted job that requires deliberate Retry. Ready output plays in the app and can be reopened without re-encoding when the saved edit is unchanged. The MP4 is temporary cache data; a missing cache file is recoverable by exporting again. P4D adds Save to Photos, Save to Files and Share below the checked output. Photos asks for add-only access only on that action, and reports Saved only after its change transaction succeeds. Denial leaves Files and Share available, with an optional Settings action. Files uses the native picker to copy the real MP4 URL; completion is recorded from the picker callback, while interactive dismissal is cancellation. Share retains the file through the system activity result and reports completed/cancelled/error without claiming a remote upload. The dedicated Photos action owns Photos saves; the Share sheet omits Save Video to avoid a second, untracked Photos path.

Delivery receipts live in Application Support/PromptPrototype/Deliveries, keyed by take UUID and saved edit revision. They survive disposable MP4 cache recreation and remain independent for each destination. A pending attempt becomes Unknown after relaunch and never resumes automatically. Check the destination before confirming another attempt. A completed Photos save disables the primary action; Save Another Copy to Photos requires confirmation. Failure/retry reuses checked output. Native pickers and pending Photos work hold their own output lease; Back and competing delivery actions wait for completion. Deleting the app original does not delete copies already saved to Photos or Files.

Recipes live under Application Support/PromptPrototype/Edits, separately from the take journal and originals. Saves validate source identity, time ranges and revisions, then replace the sidecar atomically. Corrupt or future recipes are preserved with saving blocked; original preview stays available. A write failure keeps the draft for retry.

Export jobs live under Application Support/PromptPrototype/ExportJobs and disposable outputs under Library/Caches/VideoExports. Jobs persist intent before encoding and publish Ready only after container, H.264/AAC, SDR, duration, dimensions, first/last video frames and audio presence checks. The source identity is rechecked before publication and before output playback. Capacity preflight reserves two output estimates plus 128 MiB; capacity/write faults are tested with isolated injection. Output leases prevent deletion during playback. Cancellation and recovery only clean owned derived files; saved recipes and originals remain intact. Future/corrupt job records are preserved and prevent orphan collection.

Scripts live under Application Support/PhoneScripts. Saves use synchronized staging files, atomic replacement, a previous-good backup, revision/conflict checks, corrupt-file preservation and future-schema write protection. A failed save retains the current draft in memory and shows an error; the previously saved disk snapshot remains available. Resolve an unsaved draft before terminating the app.

The device bundle ID remains `com.secondwind.teleprompter.prototype`, so installation updates the existing app and preserves its data. Do not uninstall it to update.

## P5D local diagnostics and final Simulator integration

Version 0.5.2/build 19 retains native StoreKit 2, the existing 600-second recording ceiling, and unchanged editing/export/delivery access. The physical iPhone is not updated in this slice.

One app-owned `LocalEventRecorder` is injected into the library, capture, subscription and MP4 controllers. It is not observable and never runs on reader ticks. Its bounded queue forwards typed value payloads to `LocalEventJournal` off the main actor. The Application Support `LocalEvents/events.json` file is atomic, excluded from backup, limited to the latest 500 events / 512 KiB, and prunes events older than 30 days on append. UUID UI tests use an isolated subdirectory. No diagnostic screen, network sink, content/path/error-message properties, StoreKit receipt/product IDs or Photos identifiers are added.

Deduplication uses operation + event + stage within the retained window. A pending purchase and its verified approval share one attempt with separate stages. An explicit Restore and each delivery retry have new attempts. MP4 readiness cannot suppress a later Photos/Files/Share outcome. Reopening saved output emits no duplicate result; a pending delivery recovers as unknown. Diagnostics are best effort and can be lost on queue saturation, storage failure or abrupt termination. They never block capture or certify remote uploads, renewals or production conversion statistics.

`Scripts/verify-iphone-p5.sh <booted-iPhone-Simulator-UDID>` requires the full app-host suite, named P5B/C/D native methods, script/reader/import and P4E integration regressions, the actual native event journals, and Release test-resource exclusions. `Scripts/verify_p5d_events.py` validates the two new native journeys' persisted journal contents after relaunch. No physical camera test belongs to this script.
